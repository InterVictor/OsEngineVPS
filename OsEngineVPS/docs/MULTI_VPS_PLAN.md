# Несколько VPS в OsEngineVPS: план (2026-10-05)

Статус (2026-10-05): шаг 1 (показываемые имена терминалов, `/etc/osengine/names.conf`) сделан; этапы 0-3 сделаны и проверены на живом сервере (два профиля на один и тот же VPS: четыре туннеля, терминалы доступны через оба); этап 4 («Обновить все VPS...») сделан и собран, на живых терминалах не запускался (перезапуск торговых терминалов только с ведома пользователя); внешний вид главного окна с несколькими VPS и окна Настроек проверяет пользователь.

## Что нужно

- В Настройках добавлять и удалять подключения к другим VPS; у каждого VPS своё имя (например, по имени провайдера), его можно менять.
- Окно Настроек: **вверху общее для всех VPS**, ниже **вкладки VPS**.
- Главное окно: один ряд вкладок терминалов; когда VPS больше одного, в заголовке имя VPS (`провайдер · терминал`).
- Позже (отдельная задача): автоматическая миграция терминалов с одного VPS на другой (цена, условия работы).

## Решения пользователя

| Вопрос | Решение |
|---|---|
| Строка «прямое подключение к MCP» (URL, ключ, Connect) | убрать: всё идёт через SSH-туннель |
| Вкладки главного окна | один ряд, с именем VPS в заголовке (если VPS больше одного); имя VPS задаёт пользователь |
| «Update build» | есть у каждого VPS **и** «Обновить все» в общей части (по очереди, с подтверждением на каждый VPS и показом открытых позиций) |
| Переименование терминалов | только показываемое имя, хранится на VPS (`/etc/osengine/names.conf`); ключи подключений для агентов не меняются |
| Телефон | только чтение имён, менять имя с телефона не нужно |

## Раскладка окна Настроек

```
┌ Настройки ───────────────────────────────────────────────────────────────┐
│ ОБЩЕЕ                                                                     │
│  Все VPS: Имя | Адрес | Связь | Терминалов | CPU | RAM | Сборка          │
│  Этот компьютер: SSH-ключ (путь, зарегистрирован ли), автоподключение     │
│  MCP-доступ для агентов: папки .mcp.json                                  │
│  Сборка на этом компьютере: <sha8>   [Обновить все VPS...]                │
├───────────────────────────────────────────────────────────────────────────┤
│ [ cloud4box ] [ второй VPS ] [ + ]    (правая кнопка: Переименовать / Удалить)
│  Подключение: адрес, пользователь, пароль или ключ, порт туннеля, [Подключить]
│  Терминалы: таблица + Start / Stop / Restart / Add / Remove / Rename
│  Обслуживание: Update build, Files, Clean logs, Reboot VPS, Deploy / repair, Computers...
│  Мониторинг VPS, бэкап данных, удалённый список ключей
├───────────────────────────────────────────────────────────────────────────┤
│ Журнал событий (общий, с колонкой VPS)                                    │
└───────────────────────────────────────────────────────────────────────────┘
```

### Что общее, что у каждого VPS

| Общее (вверху) | У каждого VPS (во вкладке) |
|---|---|
| список всех VPS со связью, терминалами, CPU/RAM, сборкой | адрес, пользователь, пароль, порт туннеля |
| SSH-ключ этого компьютера (файл), автоподключение при запуске | регистрация ключа на этом VPS, «Computers...» |
| MCP-доступ: папки, куда пишется `.mcp.json` | терминалы VPS и их действия |
| сборка на этом компьютере и «Обновить все» | Update build, Files, Clean logs, Reboot, Deploy / repair |
| общий журнал | мониторинг VPS, бэкап и восстановление данных |

## Как устроено сейчас (код)

- Сессия общая и статическая: `VpsRemoteSession` (~28 использований) хранит клиентов MCP по имени терминала; одно окно `RobotsVpsUi` (~1400 строк) держит один SSH-туннель и одни настройки (`Engine/RobotsVpsSettings.txt`, DPAPI).
- Локальные порты туннеля: 6510 для основного терминала, дальше по смещению порта MCP на сервере.
- `.mcp.json`: ключи `osengine-server` (основной) и `osengine-server-<имя>`; от технических имён терминалов.

## Модель данных

- `VpsProfile`: стабильный `Id`, `Name` (показываемое, меняется), `Host`, `User`, способ входа (пароль DPAPI или ключ), `LocalPortBase`, `AutoConnect`. Хранится локально на этом компьютере (`Engine/VpsProfiles.json`; секреты шифруются DPAPI). Имя VPS — метка профиля, на сервер не пишется.
- Первый запуск после обновления: текущие настройки превращаются в профиль №1 без потери данных (имя по умолчанию «VPS 1», пользователь может переименовать).
- Ключ терминала для остального кода: пара (`VpsId`, техническое имя терминала). Подписи для людей: «имя VPS · показываемое имя терминала», пока VPS один, префикса нет.
- Порты туннелей: у каждого профиля свой диапазон (по умолчанию 6510, 6610, 6710...; меняется в профиле), чтобы туннели разных VPS не пересекались.
- Ключи для AI-агентов (`.mcp.json`): у первого VPS остаются прежние (`osengine-server`, `osengine-server-binance`); у остальных `osengine-<имя VPS>-<терминал>`. Имя VPS в ключе — слаг латиницей (кириллицу и пробелы заменяем).

## Этапы

0. **Профили и миграция настроек.** Класс `VpsProfile`, чтение и запись, перенос текущих настроек в профиль №1. Вид окон не меняется.
1. **Панель одного VPS.** Содержимое `RobotsVpsUi` (SSH, терминалы, обслуживание, мониторинг, бэкап) переносится в пользовательский элемент `VpsConnectionPanel`: он владеет своим SSH-туннелем, списком терминалов, клиентами MCP и таймерами. Поведение прежнее.
2. **Оболочка Настроек.** Вверху общее, ниже вкладки VPS и «+». Добавление, переименование, удаление VPS (удаляется только профиль и туннель на этом компьютере; сервер не трогается). Строка «прямое MCP» удалена.
3. **Сессия по (VPS, терминал).** `VpsRemoteSession`, главное окно (вкладки с префиксом), `RobotsVpsLiteClone`, `McpJsonConfig`, окна файлов, робот-панели, `VpsMonitor` работают с парой (VPS, терминал).
4. **«Обновить все».** Идёт по VPS по очереди; перед каждым показывает открытые позиции и просит подтверждение; сбой одного VPS не мешает остальным; остановка при первой неудаче по желанию.
5. **Проверка.** Без покупки второго сервера: тот же VPS добавляется вторым профилем под другим именем (два туннеля на разные локальные порты). Затем на реальном втором VPS, когда он появится.
6. **Телефон** (отдельная задача): сейчас приложение работает с одним VPS; список VPS на телефоне обсуждается позже.

## Риски и правила

- Торговые ключи: переключение, обновление и перезапуск терминалов только с ведома пользователя; «Обновить все» не должна перезапускать всё без подтверждения на каждый VPS.
- Пароли и ключи: только DPAPI, в репозиторий, журналы и сообщения не попадают; адреса серверов не записываются в публичные документы.
- Удаление VPS из списка не выключает и не меняет ничего на самом сервере.
- Объём работы большой (общее состояние сейчас статическое); этапы 0–2 можно принять и проверить отдельно от 3–4.

## Дальше: миграция между VPS

Опирается на эту модель (профили, терминалы по паре VPS+имя). Заметки для будущего этапа: остановить терминал на источнике, перенести папку данных (Engine, Data, Custom, журналы позиций), ключи биржи лежат в настройках коннектора; Binance привязывает API-ключ к IP, поэтому IP нового VPS нужно добавить в Binance или выпустить новый ключ; открытые позиции остаются на бирже, поэтому переносить лучше при пустых позициях или принять паузу в управлении; для подключения через посредника (Zignaly) нужно проверить, что он разрешает.

## Что реализовано (2026-10-05)

- `VpsProfiles` (список VPS на этом компьютере, `Engine/VpsProfiles.txt`, `id|имя`; первый VPS с id 1 хранит настройки в прежнем файле `Engine/RobotsVpsSettings.txt`, остальные в `RobotsVpsSettings_<id>.txt`; общие настройки: `Engine/VpsCommonSettings.txt`, папки MCP-доступа).
- `VpsConnectionPanel` (бывшее окно `RobotsVpsUi`, теперь панель одного VPS: SSH-туннель, терминалы, обслуживание, мониторинг, бэкап); `RobotsVpsUi` стало оболочкой: вверху таблица всех VPS и общие настройки, вкладки VPS с «+», внизу общий журнал.
- `VpsRemoteSession` по паре (VPS, терминал): ключ терминала = обычное имя для первого VPS и `<id VPS>/<имя>` для остальных; `TitleOf` добавляет имя VPS, когда VPS больше одного.
- `.mcp.json`: первый VPS без изменений (`osengine-server`, `osengine-server-<терминал>`), остальные `osengine-server-v<id>-<терминал>`; удаление VPS убирает его записи.
- Порты туннелей: у нового VPS своя база (6510, 6610, 6710...), терминал берёт базу + (порт на сервере - 6500).
- Строка «прямое MCP» скрыта (вход только через SSH).
- Известные ограничения: раскладки окон графика называются по номеру робота (`Vps_<робот>_...`), у двух VPS с одинаковыми именами роботов они общие; ключ терминала первого VPS с именем вида `v2-x` читается как терминал второго VPS (не используйте такие имена).
- «Update all VPS...» в общей части: общее подтверждение со списком VPS, затем по VPS по очереди (порядок списка): показ открытых позиций терминалов, подтверждение именно этого VPS, обновление тем же кодом, что и «Update build»; не подключённый по SSH VPS пропускается; при сбое спрашивает, продолжать ли со следующим; в конце сводка.

## Миграция терминала между VPS (2026-10-05)

Кнопка «Migrate to another VPS...» в блоке кнопок терминала (Start/Stop/Restart/Remove/Rename), код `VpsMigration`, окно `RobotsVpsMigrateDialog`. Решения пользователя: после успеха источник остановлен и его автозапуск выключен (данные остаются); миграция при открытых позициях разрешена с отдельным подтверждением.

Порядок шагов: 1) на целевом VPS создаётся новый пустой терминал (сборка и роботы берутся с main этого VPS); 2) источник останавливается (пока он штатно сохраняет данные); 3) его данные пакуются и скачиваются на этот компьютер (снимок остановленного терминала); 4) данные кладутся в новый терминал, он запускается (при сбое восстановления старые данные нового терминала возвращаются); 5) ждём ответа MCP нового терминала; показываемое имя копируется; 6) автозапуск источника выключается.

Правила безопасности: если сбой до того, как данные попали в новый терминал, источник запускается обратно, а пустой новый терминал остаётся (об этом сказано в сообщении); если данные уже в новом терминале, но он не отвечает, источник НЕ запускается (два терминала с одними ключами биржи торговали бы дважды), решение за пользователем. Ключи биржи, привязанные к IP (Binance): IP целевого VPS нужно добавить в ключ до миграции (в диалоге это написано).

Проверено на живом сервере временными терминалами без ключей и роботов (migsrc -> migdst на «втором профиле» того же сервера): все шаги прошли, файл-метка из данных источника оказался в новом терминале, источник остановлен и отключён, данные источника сохранены, боевые терминалы не затронуты. Тест нашёл и помог исправить две ошибки (проверка остановки службы кодом 3; источник не запускался обратно при сбое на этом шаге). На боевых терминалах миграция не запускалась.
- Напоминание про IP: перед миграцией отдельное окно показывает IP целевого VPS (крупно, с кнопкой Copy) и путь в Binance; кнопка Continue работает только после флажка «IP добавлен» (`RobotsVpsIpReminderDialog`).
